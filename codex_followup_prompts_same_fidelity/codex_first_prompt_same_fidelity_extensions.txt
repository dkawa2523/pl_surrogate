今回のタスクは **Phase 1 のうち unetpp だけ** を実装することです。ffno、attention、coord_mlp、deeponet_pod にはまだ着手しないでください。

実装目標:
- 新しい model_id `unetpp` を追加する
- 既存 `unet` の feature 契約と target 契約を保つ
- `unetpp` は mainline-candidate として扱う
- deep supervision は Phase 1a では実装しない。config 置き場だけ準備してもよいが、挙動は off 固定でもよい
- attention は実装しない

絶対条件:
- target 名を固定しない
- target ID の真実源は `dataset.targets[].id`
- target 順序の真実源は `output_layout.vars`
- target transform の真実源は `preprocessing.scalers.target_transforms.<var>`
- `coord_feature_pack` を使う場合、train / infer / benchmark で feature 順序を一致させる
- benchmark / compare の dynamic target 前提を壊さない
- `ne / ni / Te / phi` 前提の分岐を追加しない
- 既存 `unet`, `fno`, `deeponet_plasma` の既存動作を壊さない
- `tests/fixtures` はテンプレ扱いとし、運用向けの YAML 正本は `configs/experimental/same_fidelity_low_data/` に置く

実装内容の要件:
1. 新規ファイル `src/plasma_surrogate/models/unet/unetpp.py` を追加し、`UNetPPBaseline` を実装する
   - 既存 `UNetBaseline` とできるだけ同じ wrapper API を持つこと
   - 必須メソッド:
     - `set_static_spatial_features`
     - `_resolve_spatial_features`
     - `_feature_map`
     - `forward`
     - `predict_fields`
     - `backward_raw`
     - `state_dict_numpy`
     - `load_state_dict_numpy`
   - v1 は depth=2 の nested skip 構成でよい
   - 出力は final head 1本のみでよい
   - shared output head 前提にする
   - 既存 `unet` と同じく static spatial features を扱えるようにする

2. `src/plasma_surrogate/models/mlp/io.py` を更新する
   - `build_model_from_name` に `unetpp` を追加する
   - checkpoint save/load に `model_type == "unetpp"` を追加する
   - meta には少なくとも以下を保持すること:
     - model_type
     - input_dim
     - grid_shape
     - out_channels
     - output_keys
     - backend
     - input_feature_channels
     - with_rho_eff_head
     - head_mlp
     - conv_cfg
     - output_heads

3. `src/plasma_surrogate/train/model_dispatch.py` を更新する
   - `unetpp` を既存の unet-like torch branch に組み込む
   - `input_features.mode=geom_feature_pack` を mainline-candidate 条件として扱う
   - `require_pack` / distance transform / coord feature scaling は既存 `unet` と同じ helper / 流れを使う
   - strict validation は再利用できるなら既存 `_validate_unet_like_mainline_contract(...)` を再利用し、必要なら `unetpp` に対する分岐だけ最小追加する
   - `train.unetpp.target_family=allvars`
   - `train.unetpp.target_vars == output_layout.vars`
   - `train.unetpp.model_cfg.output_heads.mode=shared`
   - `train.unetpp.selection.mode=best_val_allvars_balance`
   を mainline-candidate の前提として検証すること

4. config テンプレートを追加・更新する
   - `configs/experimental/same_fidelity_low_data/unetpp_template.yaml` を docs に合わせて使える状態にする
   - feature 既定は `[x, y, mask_plasma, distance_signed, distance_any]`
   - `input_features.mode=geom_feature_pack`
   - `require_pack=error`

5. テストを追加する
   - unit test:
     - `tests/unit/models/test_unetpp_model.py`
     - `tests/unit/train/test_model_dispatch_unetpp.py`
   - integration smoke:
     - `tests/integration/test_train_unetpp_smoke.py`
     - `tests/integration/test_infer_unetpp_smoke.py`
   - 必要最小限でよいが、build/load/train/infer の一連が通ることを確認できるようにする

6. fixture を追加する
   - `tests/fixtures/benchmark_periodic_real_m7_unetpp_isolated_mainline.yaml`
   - ただし profile lock や dynamic target 契約を壊さないこと

実装方針:
- まず repo を読んで、既存 `unet` の wrapper API、checkpoint 形式、dispatch の流れを短く要約する
- その後で変更計画を箇条書きで示す
- その計画に沿ってコードを編集する
- 変更は最小差分を優先し、大規模 refactor はしない
- 既存分岐を壊さず、unet-like torch branch に自然に組み込む
- deep supervision や attention のための過剰な一般化はまだ入れない
